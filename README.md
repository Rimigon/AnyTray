# AnyTray

Фоновая утилита для Windows 10/11, которая скрывает **любое** обычное desktop-окно в
системный трей — даже если приложение само не умеет «свернуть в трей». Дополнительно
добавляет визуальную кнопку **«Hide to Tray»** в заголовок окна (overlay).

Модель: AnyTray не встраивает чужую иконку в трей. Он скрывает чужое окно
(`ShowWindow(SW_HIDE)`) и управляет им через **собственную** tray-иконку и меню.

---

## Возможности (MVP)

- Скрытие активного окна по **глобальной горячей клавише** (по умолчанию `Ctrl+Alt+H`).
- Скрытие окна **средним кликом (колёсиком) по его заголовку** — работает на ВСЕХ приложениях
  (Telegram, VS Code, браузеры). По умолчанию показывает мини-меню «Свернуть в трей»;
  в настройках можно включить мгновенное скрытие без меню.
- Скрытие любого открытого окна из меню трея **«Скрыть окно ▸»**.
- Скрытие окна кликом по **overlay-кнопке** в заголовке (только окна с системным заголовком).
- Список скрытых окон в контекстном меню трея (с именем процесса и иконкой).
- **Restore** одного окна и **Restore All**.
- Автоудаление из списка, если скрытое приложение закрылось.
- **Безопасный выход**: при закрытии AnyTray все скрытые окна восстанавливаются.
- **Crash-recovery**: список скрытых окон персистится; после аварийного завершения
  при следующем запуске предлагается восстановить ещё живые окна.
- Поддержка нескольких окон одного процесса (ключ — `hwnd`).
- Автозапуск с Windows, настройка горячей клавиши, вкл/выкл overlay, режим показа
  overlay (всегда при фокусе / только при наведении), чёрный список процессов для overlay.
- Один экземпляр (single instance), файловое логирование.

## Архитектура

```
Native/          P/Invoke-обёртки, константы, структуры, Win32Window
Models/          HiddenWindowInfo, AppSettings, HotkeyDefinition, OverlayDisplayMode
Services/        WindowManager, TrayService, HotkeyService, OverlayButtonService,
                 SettingsService, AutostartService, ProcessWatcher, SessionStateService
Infrastructure/  SingleInstance, Logger, DpiHelper, IconHelper
ViewModels/      MainViewModel («мозг»), SettingsViewModel
Views/           OverlayButtonWindow, SettingsWindow
App.xaml(.cs)    composition root, жизненный цикл, restore-all-on-exit
```

**Overlay-кнопка (ключевой механизм).** `OverlayButtonService` ставит **один** набор
глобальных `SetWinEventHook` (OUTOFCONTEXT) на UI-потоке WPF — там работает message loop,
поэтому колбэки приходят на UI-поток без маршалинга, а делегат хука хранится в поле
(иначе его соберёт GC). По событиям окон (`FOREGROUND`, `LOCATIONCHANGE`,
`MINIMIZESTART/END`, `OBJECT_SHOW/HIDE`, `OBJECT_DESTROY`) overlay позиционируется/
прячется/уничтожается. `LOCATIONCHANGE` дебаунсится одноразовым `DispatcherTimer` (~16 мс),
поэтому при перетаскивании окна нет polling и CPU в простое ≈ 0%.

Позиция кнопки вычисляется в **физических пикселях** и применяется через `SetWindowPos` —
это убирает DIP-математику при позиционировании и «бесплатно» решает мультимониторные
конфигурации. Для поиска системных кнопок используется
`DwmGetWindowAttribute(DWMWA_CAPTION_BUTTON_BOUNDS)` (точные границы группы кнопок).
Если окно полностью рисует свой заголовок без системных кнопок (например, VS Code и
некоторые Electron-/UWP-окна), границы пустые → overlay **не показывается** (чтобы не
перекрывать чужие кнопки); такое окно всё равно можно скрыть по горячей клавише.
У развёрнутых (maximized) окон компенсируется 8px-«вылет» рамки за край экрана.

> **Стратегия MVP:** overlay показывается на **текущем окне в фокусе** (один переиспользуемый
> overlay), а не плодит десятки невидимых окон. Это удовлетворяет требованию «кнопка на каждом
> обычном окне» (она появляется на окне, с которым работает пользователь). Per-window словарь
> overlay-окон — кандидат на v2.

## Сборка и запуск

Требуется **.NET 8 SDK** (проверено на 8.0.421), Windows 10/11 x64.

```powershell
# из папки проекта
dotnet build AnyTray.csproj -c Release -p:Platform=x64

# запуск
.\bin\x64\Release\net8.0-windows\AnyTray.exe
# либо
dotnet run --project AnyTray.csproj -c Release
```

Приложение стартует **без окна**, появляется иконка в трее. Правый клик — меню,
двойной клик — настройки.

**Файлы данных** (`%APPDATA%\AnyTray\`):
- `settings.json` — настройки;
- `hidden-session.json` — список скрытых окон (для crash-recovery; пуст при штатном выходе);
- `logs\anytray.log` — лог.

**Права администратора.** По умолчанию AnyTray запускается без повышения (`asInvoker`).
Чтобы управлять окнами приложений, запущенных от администратора (ограничение UIPI),
пересоберите с `requestedExecutionLevel level="requireAdministrator"` в `app.manifest`.

## Известные ограничения

- **Окна с правами администратора (UIPI):** обычный (medium-IL) AnyTray не получает их
  WinEvents и не может надёжно ими управлять → нет overlay, hotkey-hide может не сработать.
  Решение — запуск AnyTray от администратора (см. выше).
- **Приложения с полностью кастомным заголовком без системных кнопок** (VS Code, Telegram и
  часть Electron-/Qt-приложений): overlay-кнопка **не показывается** — Windows не отдаёт
  границы их собственных кнопок, и кнопка лишь перекрывала бы чужие. Такие окна можно
  скрыть **горячей клавишей** или через меню трея **«Скрыть окно ▸»** (список всех открытых окон).
  *(Проверено: overlay корректно появляется в File Explorer, Windows Terminal, Chromium-
  браузерах, UWP/Калькуляторе и обычных Win32/WinForms/WPF-приложениях.)*
- **Chromium-браузеры:** overlay позиционируется по системным границам кнопок; их собственные
  кнопки могут быть нарисованы чуть иначе, поэтому возможно небольшое смещение.
- **UWP / WinUI 3:** overlay поддержан для `ApplicationFrameWindow` (Калькулятор, Фото,
  Параметры). Приостановленные/скрытые на другом рабочем столе отсекаются `DWMWA_CLOAKED`.
- **Полноэкранные / exclusive-fullscreen игры (DirectX):** нет стандартного заголовка —
  overlay не показывается (окно отсекается предикатом).
- **Окна без `WS_CAPTION`** (borderless, tool-окна): исключены.
- **`SetForegroundWindow`** может не отдать фокус из-за foreground-lock Windows — окно всё
  равно становится видимым.
- При перетаскивании окна между мониторами с разным DPI возможна кратковременная (≈16 мс)
  задержка перепозиционирования overlay.

## План тестирования (ручной)

**Ядро (hotkey + трей):**
1. Notepad/Paint: `Ctrl+Alt+H` → окно исчезает с экрана и из панели задач, остаётся в
   Диспетчере задач → Restore из трея → окно вернулось на то же место.
2. Окно в maximized: развернуть → скрыть → восстановить → состояние сохранено.
3. Скрыть 3 окна → в меню 3 пункта → закрыть одно извне → пункт исчезает (в течение ~2.5 с)
   → Restore All → остальные вернулись.
4. Выход из AnyTray при 2 скрытых окнах → оба восстановлены.
5. Второй запуск AnyTray → завершается (single instance).
6. Включить автозапуск → перезагрузка → AnyTray в трее.
7. Crash-recovery: скрыть окно, снять процесс AnyTray через Диспетчер задач, запустить
   снова → предложено восстановить окно.

**Overlay-кнопки:**
8. Notepad: кнопка слева от «свернуть»; перетаскивание/ресайз → следует; minimize → прячется;
   restore → возвращается; закрытие → overlay исчезает (без «осиротевших» окон).
9. Окно на втором мониторе с DPI 150% → корректные позиция и размер; перенос между мониторами
   разного DPI → пересчёт.
10. Клик по overlay → окно скрывается так же, как по hotkey; Restore из трея → overlay снова на месте.
11. Режим «только при наведении» → overlay появляется при наведении на заголовок.
12. Idle-CPU: ничего не двигается → ≈0% CPU (подтверждает event-driven без polling).

> Базовая верификация уже выполнена автоматически: проект собирается без ошибок/предупреждений,
> приложение стартует и инициализирует все сервисы без исключений, а нативная техника
> `SW_HIDE` / `SetWindowPlacement` проверена на живом окне.
